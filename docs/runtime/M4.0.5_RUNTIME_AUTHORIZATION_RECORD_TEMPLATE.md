# M4.0.5 Runtime Authorization Record Template

Use one record per live validation or controlled execution scope. Replace values with approved non-secret evidence. Never place passwords, raw connection strings, private keys, or access tokens in this record.

## Record

```text
record_id: <record-id>
milestone: M4.0.5
execution_scope: <structural-validation | live-readonly-validation | controlled-migration>
runtime_environment: <local | staging | production>
target_id: <approved-target-id>
target_host: <approved-host>
target_port: <approved-port>
target_database: <approved-database>
database_url_source: <local-env | process | secret-store>
database_url_fingerprint: <non-secret-fingerprint-or-redacted>
migration_set: <migration-identifiers-or-not-applicable>
operator: <named-operator-and-role>
approval_reference: <external-approval-reference>
authorized_release_owner: <named-owner-or-not-applicable>
approval_timestamp: <ISO-8601-timestamp>
approval_expiry: <ISO-8601-timestamp-or-not-applicable>
backup_artifact_name: <artifact-name-or-not-applicable>
backup_storage_location: <approved-storage-reference-or-not-applicable>
backup_verification: <verified-with-timestamp-or-not-applicable>
rollback_authority: <named-authority>
rollback_reference: <runbook-or-record-reference>
validation_evidence: <read-only-validation-record-references>
failure_stop_conditions: <recorded-stop-conditions>
decision: <BLOCKED | READY_FOR_CONTROLLED_EXECUTION | EXECUTED>
decision_timestamp: <ISO-8601-timestamp>
```

## Decision States

- `BLOCKED`: one or more required evidence items are missing, invalid, expired, or failed.
- `READY_FOR_CONTROLLED_EXECUTION`: all required pre-execution evidence is approved; no execution is implied.
- `EXECUTED`: the approved scope was executed and the resulting evidence is attached or referenced.

## Evidence Rules

- `execution_scope`, environment, target, operator, approval reference, backup evidence, rollback authority, validation evidence, and decision are mandatory for live or controlled records.
- `database_url_fingerprint` may identify a target without exposing credentials.
- Raw `DATABASE_URL` values, passwords, root credentials, private keys, and tokens are prohibited.
- A `READY_FOR_CONTROLLED_EXECUTION` decision does not override a separate identity-specific authorization gate.
